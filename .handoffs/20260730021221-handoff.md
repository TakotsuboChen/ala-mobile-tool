## 3. 决策与理由

- **"三个响应曲线不生效"根因是方向反了** [V]——旧 `applyCurve` exponent 全 ≥1（LINEAR=1, QUADRATIC=2,
  EXPONENTIAL=2.5），全是"先慢后快"（小行程被压扁）。用户想要的拟真手感是"先快后慢"（30%行程→60%输出），
  需要 exponent < 1。解 0.3^exp = 0.6 得 exp ≈ 0.42。所以不是代码没跑到，是曲线方向与期望相反。
  新实现：LINEAR=1（恒等），EXPONENTIAL=0.42（ease-out，先快后慢）。
- **曲线精简成两个选项** [V]——用户拍板：只保留"不修改（线性）"和"拟真（指数）"。删 QUADRATIC，
  旧 `quadratic` 配置值映射到 EXPONENTIAL 保兼容。否决：保留三选项，因 QUADRATIC 与拟真方向相反、
  无实际用途，徒增选择困惑。
- **单/双踏板是 view 拓扑问题** [V]——单踏板是上下分区（transition 分界，死区有意义）；
  双踏板是两个独立全行程 view（无 transition，死区无意义）。用 `PedalRole` enum 区分，onDraw/updateValues
  分支处理。否决：用两个不同 View 类，因逻辑高度同构（都是 Canvas + onTouch），分支更省代码。
- **双踏板刹车独立 position** [V]——双踏板两个 view 需各自独立位置可调，加 `brakePosition` 配置字段
  和 `DEFAULT_BRAKE`（在 pedal 左侧）。edit layer 各自独立保存到 `KEY_BRAKE_POSITION`。
- **死区/过渡点条件显示** [V]——这两项只在单踏板上下分区时有意义（消除中间误触、设分界线）；
  双踏板各自全行程无需它们。用 `if (pedalMode == SINGLE)` 守卫，OFF/DUAL 完全隐藏。
- **JSON 向后兼容迁移** [V]——`enable_control_replacement: bool` 升级成 `pedal_mode: string`，
  `pedal_curve` 拆成 `throttle_curve`+`brake_curve`。读时优先新 key，回退旧 key 并做值映射
  （true→SINGLE, false→OFF, quadratic→EXPONENTIAL）。写时只写新 key。老用户升级后配置不丢失。
- **native 签名不变** [V]——`enableControlReplacement` 作为 JNI 参数名保留，Java 层从 `pedalMode != OFF`
  派生。避免改 native 签名 + C 代码。`disableAutoGear` 也仍由 `enableManualShift` 派生，不变。
- **下拉用 OverlayDropdownPreference 而非自造** [V]——miuix 自带组件，和原"响应曲线"下拉一致，
  视觉统一。否决：自造 Row+DropdownMenu，因重复造轮子且样式不一致。

## 5. 已知坑

- **加/改 `ModConfig.Settings` 字段必同步所有构造点** [V]——`ModConfig.defaultSettings()`、
  `ModConfig.read()`、`ConfigMainScreen.remember{}`、`ConfigMainScreen.saveNow`、`PedalOverlayView` 默认参数。
  漏一个编译失败。本次改了 5 处（pedalMode/throttleCurve/brakeCurve/brakePosition + 删 enableControlReplacement/curve）。
- **`PedalCurve` 精简后旧值兼容** [V]——`from()` 必须处理 `quadratic` 旧值→EXPONENTIAL，否则老用户升级后
  曲线静默回退到 LINEAR，失去非线性感。
- **`PedalMode` 迁移必须处理旧 `enable_control_replacement`** [V]——`migratePedalMode()` 先看新 key，
  没有再从旧 bool 派生（true→SINGLE, false→OFF）。否则老用户升级后踏板配置丢失。
- **双踏板判空不能用 pedalView 单独判** [V]——dual 模式 pedalView 和 brakeView 都应存在；
  toggle 判空条件改成 `pedalView == null && brakeView == null && pedalMode != OFF`。
  OFF 模式两者都 null 是正常态，不应触发重复 add。
- **`applyCurve` exponent 方向** [V]——exponent < 1 是 ease-out（先快后慢），> 1 是 ease-in（先慢后快）。
  拟真踏板要前者。旧代码用 ≥1 是 bug，不是"不生效"。
- （搬运自旧 HANDOFF，仍有效）
- **`archive: false` 对 apk 有效但 CLI 误导** [V]——验证用 curl/浏览器。
- **`gh release view` asset name 转义空格成点号** [V]——看浏览器。
- **AGP ApiLevel 整数比较** [V]——复制 platform 后必须 sed `37.0`→`37`。
- **AGP inconsistent location 检查** [V]——必须改 package.xml `path` + source.properties `Pkg.Path`。
- **Google SDK 仓库未发布 `platforms;android-37`** [V]——GitHub runner 预装 `android-37.0` 可复制改路径。

- **lint baseline 不锁 AGP AAR metadata 检查** [V]——AAR metadata 必须从根上修。
- **miuix 0.9.3 `minCompileSdk=37` 硬要求** [V]——不能降 compileSdk。

- **pairip 壳 relayout 漂移** [?]——用 `event.rawY - settings.pedalPosition.topPx()`。

- **keystore 解码 step 的 `KEYSTORE_PATH` 只在解码成功时设** [V]——`if: env.KS_B64 != ''` 守卫整个 step。
